# WOKKER Control — план редизайна Soft Depth

## Цели и границы
Сделать рабочую админ-панель визуально спокойной, выразительной и удобной для управляющего. Изменения UI не должны изменять существующие API, роли, бизнес-логику и модель данных. Проект — веб-приложение, Telegram-интеграция вне текущего этапа.

## Этап 1 — дизайн-система и главная (этот PR)
- Светлый нейтральный фон, мягкая глубина через два уровня теней, тонкие границы, радиусы 12–22px.
- Семантические CSS-токены, единый акцент и доступные состояния фокуса; поддержка reduced motion.
- Четыре существующих показателя из `/api/admin/dashboard/summary` без вымышленных данных или дополнительных запросов.
- Две рабочие панели: открытые вопросы и новые сотрудники; переходы к соответствующим разделам.
- Адаптивные сетки: четыре / две / одна карточка по ширине экрана.
- Пустые состояния, загрузка, ошибки и ручное обновление.
- Дизайн подключён отдельными файлами для облегчения отката.

## Этап 2 — навигация и единые компоненты
- Группы навигации: Управление, Персонал, Обучение, Коммуникации, Система; скрытые по роли пункты не показывать.
- Единые кнопки, поля, модальные окна, теги статусов, таблицы, уведомления.
- Проверить мобильное меню, доступность клавиатурой и контраст.
- Убрать/реализовать неработающие элементы, например отключённый поиск и кнопку уведомлений.

## Этап 3 — рабочие сценарии
- Сотрудники: поиск, фильтры, карточка сотрудника, ясные действия с подтверждением.
- Медкнижки: просроченные / истекающие / действующие, понятные сроки и приоритеты.
- Рестораны и табели: быстрый выбор ресторана и контекстные действия, только при наличии проверенных API.
- Обучение и модерация: единые статусы, списки и понятная очередь действий.

## Этап 4 — техническое качество
- Разделить монолитный `admin.js` на модули без смены API.
- Отдельно рассмотреть хранение токенов в `localStorage` и токен в URL файла; исправление требует согласованной серверной миграции.
- Автотесты пользовательских сценариев и проверка разных ролей.
- Тестировать на iPhone и десктопе; проверить Lighthouse, контраст, размеры touch targets.

## Критерии приёмки этапа 1
- Дашборд использует прежний endpoint и отображает те же четыре метрики.
- Нет новых разрешений, внешних сервисов, секретов и миграций БД.
- Ссылки вопросов и сотрудников работают; интерфейс читаем на мобильном.
- При ошибке API нет ложных нулевых показателей, есть понятное сообщение.
- PR не объединяется автоматически.
